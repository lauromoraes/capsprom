\subsection{Dataset preprocessing and construction}

The active experimental dataset scope in this work is restricted to the final
intra-source processed datasets located in
\texttt{data/processed/assembled\_datasets/intra/} and to their strict-DNA
cleaned copies. These datasets were derived from four source groups: Bhandari et
al., CDBProm, CNNProm, and GraphPro. Other raw files or exploratory artifacts
present in the repository were not considered part of the active experimental
dataset unless represented in this final intra-source directory. The experimental
unit is one 81 bp sequence window; therefore, each row of a processed CSV file
corresponds to one independent sequence-level example used for feature encoding
and classification.

The included sources use heterogeneous file formats, including FASTA files,
gzip-compressed FASTA files, and line-oriented text files. To ensure a uniform
experimental representation, source records were first converted into a common
FASTA naming scheme encoding the class, source study, organism type, dataset
identifier, number of records, and original sequence length. Promoter sequences
were assigned label $1$, whereas non-promoter sequences were assigned label $0$.

All model-ready sequences were normalized to a fixed length of 81 bp around the
transcription start site (TSS). The fixed window contains 60 bp upstream of the
TSS, the TSS nucleotide itself, and 20 bp downstream. This window definition was
adopted to maintain compatibility with the promoter-region representation used
by the GraphPro and CNNProm studies for prokaryotic datasets, while applying the
same fixed input size to all active sources. Because the original sequence
windows differ across the included sources, the TSS coordinate used for cropping
was defined per source dataset. GraphPro sequences of length 81 used TSS
position 60; CNNProm sequences used position 60 for 81 bp windows and position
200 for 251 bp windows; CDBProm sequences used position 60 for 100 bp windows
and position 500 for 1001 bp windows; and Bhandari et al. sequences used
position 700 for 1000 bp windows.

coordinates used to obtain the standardized 81 bp windows.

After cropping, promoter and non-promoter FASTA files were paired by source
study, organism type, and dataset identifier. Each pair was converted into CSV
files containing two fields: \texttt{sequence}, the 81 bp DNA sequence, and
\texttt{label}, the binary class label. The final intra-source datasets use a
filename convention that records the source study, organism type, dataset name,
positive count, negative count, and partition. The train/test split used in this
section is the fixed split encoded in the final intra-source CSV files; no
additional repartitioning is performed during model input preparation.

\subsubsection{Quality control and final dataset definition}

A strict DNA cleaning step was then applied to produce the model-ready cleaned
intra-source directory. This step removed only rows whose sequence contained
symbols outside the alphabet \{A, C, G, T\}; no original final CSV file was
overwritten. This policy ensures that all subsequent encodings, including
one-hot, k-mer, and physicochemical encodings, operate over the same unambiguous
DNA alphabet. Across the 58 final intra-source CSV files, 338 rows were removed
from 12 files, corresponding to approximately 0.02\% of the 1,829,262 original
sequence-level examples. The cleaning step therefore had minimal impact on the
overall dataset size while removing incompatible ambiguous IUPAC symbols. After
cleaning, all 58 cleaned CSV files passed validation for 81 bp sequence length,
binary labels, class-count consistency, and strict DNA alphabet compliance. The
strict-DNA intra-source directory is the official model-ready data source used
for the experiments described in this work.

These strict-DNA sequence-level datasets provide the input for the feature
engineering stage. In the subsequent experimental pipeline, each 81 bp sequence
can be represented using k-mer frequency vectors, one-hot matrices,
physicochemical property matrices, DNA-BERT embeddings, or controlled
combinations of these feature blocks depending on the classifier architecture.
