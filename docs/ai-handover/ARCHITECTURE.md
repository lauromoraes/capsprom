# Architecture

## Repository layout

- `specs/`: scientific and execution contracts; read before behavioral changes.
- `configs/`: versioned YAML experiment, data, release, and policy contracts.
- `src/capsprom/`: installable Python package and CLI.
- `scripts/`: explicit builders, audits, campaign launchers, and summarizers.
- `tests/`: focused unit and workflow fixtures.
- `data/`: raw references and processed datasets; datasets are not Git deliverables.
- `outputs/`: ignored run state, MLflow databases, checkpoints, predictions, and reports.
- `manifests/`: lightweight project status and remote-job registry.
- `docs/`: reports, thesis sources, operational notes, and this handover.

## Code responsibilities

- `config.py`, `cli.py`, `runner.py`: validated YAML-to-run entry path.
- `data/`: loading, sequence validation, reconstruction, duplicate/collision handling, group-safe splitting, and audits.
- `features/`: k-mer, one-hot, physicochemical, sequence-derived, and DNA-BERT interfaces.
- `models/`: classical, sequence-CNN, and basic CapsProm implementations.
- `experiment.py`, `evaluation.py`, `tracking.py`: classical training, metrics, and MLflow.
- `canonical_neural.py`, `neural_training.py`, `neural_experiment.py`: canonical fold plans, resumable neural state, job claiming, and MLflow parent/child runs.
- `statistical_comparison.py`: paired and cluster-aware comparison primitives.
- `remote_operations.py`, `project_status.py`, `state.py`: remote job registry, compact status, hashes, and atomic state.

The requested refactor boundary from `AGENTS.md` has effectively begun: model, tracking, evaluation, and runner modules exist. Avoid moving behavior back into a monolith.

## Processing flow

`YAML contract -> strict config validation -> dataset/hash resolution -> biological validation -> feature blocks -> model training -> validation/selection -> locked test evaluation (only when released) -> metrics/predictions/artifacts -> MLflow + atomic state -> summary/report`.

For canonical neural work, five deterministic training folds select an epoch using the lower median fold-best epoch, followed by a full-training refit and external-test evaluation only after their separate gates open. Fold state is manifest-bound and resumable; a different manifest or configuration requires a new versioned path.

## State and immutability

Versioned YAML becomes an immutable contract after its state path exists. Experiment state is written atomically and includes hashes. Do not edit a used contract in place; create a successor version and new state/output directory. The authoritative operational view is generated by `make status`; persist a checkpoint with `make status-snapshot`.
